# 기존 SST 번역의 재번역·검수 자료

이번 추가 번역 이전에 사용하던 SST 번역을 나중에 일괄 검토하기 위한 자료입니다. **아직 재번역하거나 검수를 완료한 자료가 아닙니다.** 패처가 이 폴더를 읽어서 게임에 적용하지 않습니다.

## 범위

- Genesis 8.8.32 패처에 선택된 기존 SST 번역 **177,453개 항목**, **235,689개 적용 위치**.
- 250개씩 **710개 JSON**으로 분할. 같은 영어라도 적용된 한국어가 다르면 별도 항목입니다.
- 이번 추가 번역 및 의미/최종 검수의 원문 집합은 보수적으로 전부 제외했습니다. 제외 목록의 출처 해시는 `legacy/manifest.json`에 기록합니다.
- 직접 복사하는 본편·DLC 보충 한패 Strings 26개는 이 자료에 포함하지 않습니다. 해당 파일은 원문/번역 대응을 별도로 확보해야 합니다.
- 사용자가 8.8.1용이라고 설명한 SST가 출처이며, 각 SST의 모든 항목이 반드시 같은 모드팩 버전에서 만들어졌다고 보증하지 않습니다.

## 파일

- [`GLOSSARY.md`](GLOSSARY.md): 기존 추가 번역의 작업 용어집과 문체·태그 규칙.
- [`legacy/manifest.json`](legacy/manifest.json): 총량, 출처 해시, 배치 파일과 초기 체크섬.
- `legacy/batches/legacy-0001.json`부터: 수정 가능한 번역·검수 항목.

## 항목 구조

| 필드 | 의미 |
|---|---|
| `id` | 원문과 현재 적용 번역에 기반한 안정적인 항목 ID |
| `source_en` | 제네시스 플러그인/Strings의 최종 영어 원문 |
| `legacy_ko` / `legacy_variants` | 수정 전 SST 번역과 동일 적용값의 원래 변형 |
| `current_patch_ko` | 현재 릴리즈에서 사용하는 번역; 일부는 표기 보정됨 |
| `proposed_ko` | 향후 새 번역. 초기값 `null`은 아직 작성하지 않았다는 뜻 |
| `review_status` | 초기 `pending`; 승인 완료가 아님 |
| `review_flags` / `review_notes` | 자동 점검 의심 사항과 검수 메모 |
| `locations` | 모드 상대 경로, 레코드·FormID·필드·인덱스 또는 StringID |
| `sst_references` | 해당 기존 번역이 발견된 SST 파일과 원래 식별자 |
| `source_scope` / `priority` | 바닐라 원문 대조 결과와 작업 우선순위 |
| `human_reviewed` / `in_game_verified` | 실제 사람 검수·게임 검증 여부. 초기값 모두 `false` |

`locations[].vanilla_source_en`은 제네시스 영어와 달랐던 바닐라 비교 원문입니다. **번역의 기준으로 바꿔 사용하지 않습니다.** JSON의 영어·한국어·태그·줄바꿈은 원형대로 보존했습니다.

## 우선순위와 비용

| 우선순위 | 항목 수 | 작업 |
|---|---:|---|
| 0 | 111 | 표기 보정·한글 미포함 등 기초 점검 플래그 |
| 1 | 40,667 | 제네시스 변경 Strings 또는 플러그인 텍스트 |
| 2 | 23,572 | 대응 바닐라 영어를 확보하지 못한 항목 |
| 3 | 113,103 | 대조 위치의 바닐라 영어가 같은 항목 |

우선순위는 품질 판정이 아닙니다. 플러그인 텍스트는 바닐라 레코드 전체와 비교하지 않았으므로 전부 제네시스 신규/변경 문구라고 주장하지 않습니다. 바닐라 참조는 현재 설치된 원본 Localization BA2에서 **읽기만** 했으며 해당 파일명은 manifest에 남깁니다. 참조가 없는 DLC나 동적 항목은 변경 여부를 추측하지 않습니다.

처음에는 우선순위 0·1에서 대사/퀘스트를 중심으로 진행하는 편이 좋습니다. 배치 파일 전체를 한 요청에 넣지 말고 **20~50개 또는 원문 약 6,000자 이하**로 잘라 처리합니다. 파일의 상대 경로나 ID만으로 화자와 상황이 확정되는 것은 아닙니다.

## 나중에 진행할 순서

1. 원본 `legacy_ko`, `source_en`, `id`, 출처와 위치는 변경하지 않습니다.
2. `GLOSSARY.md`와 필요한 위치 정보를 읽고 새 번역을 `proposed_ko`에 작성해 `retranslated`로 표시합니다.
3. 별도 검수로 의미·누락·용어·화자·태그·줄바꿈을 확인합니다. 수정이 필요하면 메모를 남기고, 문맥이 부족하면 `context_needed`로 보류합니다.
4. 구조 검사를 통과한 항목은 `qa_passed`, 실제 채택을 결정한 항목만 `approved`로 표시합니다. AI 결과만으로 `human_reviewed`를 켜지 않습니다.
5. 승인 항목을 별도 오버레이로 만들고 기존 패처의 검사·백업·미리보기 절차를 거친 후 새 릴리즈에 반영합니다. JSON을 곧바로 덮어쓰는 설치 방식은 아닙니다.

`approved`라도 사람이 원문·번역을 실제로 확인하지 않았다면 `human_reviewed=false`를 유지합니다. 게임에서 확인한 항목만 `in_game_verified=true`로 표시합니다. 빈 번역을 승인하려면 기술 식별자/표시 제거 등 명확한 이유를 별도로 남겨야 합니다.

## 재현과 검증

```powershell
python scripts/export_legacy_review.py --audit-dir <기존-audit-output> --output-dir <비어있는-새-출력폴더>
python scripts/classify_legacy_review.py --base-data <Steam-Starfield-Data> --review-dir <새-출력폴더>
python scripts/validate_legacy_review.py --review-dir <새-출력폴더> --verify-snapshot
```

재추출은 비어 있는 별도 출력 폴더에서 실행합니다. 원래 감사 CSV와 당시 표기 보정 규칙이 필요하며, API 키나 네트워크 번역 요청은 필요하지 않습니다. 저장소의 기존 검토 자료를 검사하려면 `python scripts/validate_legacy_review.py`를 실행합니다. 검수 후에는 초기 체크섬과 달라지는 것이 정상이므로 `--verify-snapshot`은 미수정 초기 자료에만 사용합니다.

이 자료는 기존 사용자 번역과 설치 파일에서 추출한 번역 검토용 텍스트입니다. 원본 게임·모드 전체나 API 키·개인 경로·작업 로그를 포함하지 않으며, 원저작물의 권리를 새로 부여하는 라이선스를 주장하지 않습니다.
